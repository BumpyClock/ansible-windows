# Review fixes, 2026-10-25

The fixes address all five prioritized performance findings and all five code-quality findings in the [performance review](2026-10-25-performance-review.md) and [quality review](2026-10-25-code-quality-review.md). Source and regression checks establish the behavior changes below. The measured gains are limited to managed helper workloads. Packaged UI responsiveness and full meeting throughput remain unmeasured.

## Changes and evidence

| Finding | Implemented change | Evidence and remaining limits |
| --- | --- | --- |
| P1. Repeated device hashing | An engine owns a reusable runtime identity. Warm keys recheck handle identity, DLL membership, and hardware/driver identity. The main DLL is hashed once. Cache version advances to v4. | Tests cover zero warm content reads, changed bytes, replacements with equal length/time, added DLLs, changed sample, hardware, and request fields. Warm helper measurements below. |
| P2. Transcript redraw | A constrained ListView virtualizes typed rows. A projection preserves unchanged row objects and only notifies changed properties. Bottom following no longer forces UpdateLayout. | Seven projection tests cover 1,800 unchanged rows plus append, earlier corrections, names, cleanup, and expansion. NativeAOT package verification covers XAML compilation. Actual scrolling, selection, realized control counts, and frame times require UI testing. |
| P3. Blocking saves | One owned persistence worker accepts one in-flight snapshot and one latest pending revision. Progress queues snapshots without waiting for disk. Pause, End, and close flush required revisions; shutdown joins the worker. Cleanup publishes its new document only after a successful durable write. | Slow/failing-store tests cover bounded coalescing, ordering, flush waits, failures, retry, and preservation of original wording. There is no intentional save delay. A crash can lose revisions newer than the last successful save; disk stalls have no fixed time bound. Full-document serialization and fsync remain. |
| P4. History loads | The store retains validated summaries, invalidated by file identity. Opening a meeting loads its full document. Startup recovery is independently owned and joined. History refresh ignores deactivation and hidden-page activation. | Tests cover changes, replacements, removal, corrupt files, recovery, and opening current content. The first scan still validates full documents one at a time. Warm listing still checks every file identity. |
| P5. Cumulative attribution | Reuse unchanged native token objects and the speaker-activity timeline. Build turns without allocating intermediate word objects. Publish once after an audio chunk drains its ASR events. Skip empty speaker-name evidence while clearing obsolete automatic names. | Tests cover revised old tokens, changed activity at the same count, changed processed bounds, overlap, final replacement, and manual names. Allocation measurement below. Attribution still traverses cumulative speech; no stable-prefix assumption was introduced. |
| Qualification gap | Auto includes synchronous incremental managed attribution, warms up once, then validates and times three runs. Streaming state resets between trials. Selection uses the median. | Public-sample validation and native execution checks are recorded below. This worker still excludes persistence, meeting-name matching, and WinUI. |
| Q1. Misreported insertion | Failed key release is labeled “Not verified” and is no longer classified as sent. The explanation names the unreleased input keys. | A test passes a partial paste chord through the real input policy, delivery result, and history projection. It asserts no automatic replay and no success claim. |
| Q2. Test-only callback | Delete the optional dictation preview callback and its UpdateFacts path. | Session tests use the existing state observer and engine boundaries. No production caller needed the callback. |
| Q3. Mixed operation owner | Typed operation owners separate connection, model maintenance, file, replay, and microphone lifetimes. Required inputs are constructor state. Shutdown and admission stay centralized. | 109 session tests cover cancellation, rollback, retained candidate ownership, and close retry. This is an ownership change, not a reduction in line count. |
| Q4. Unused analytics | Delete unread summary totals and their calculations. Keep actual UI counters and nullable speech pace. | Usage and home projection tests retain authoritative speech-count semantics. |
| Q5. Dead surface | Delete the unused cleanup interface, meeting-only device-summary contract member, PageCanvas width property, and confirmed unused custom design resources. | Repository reference checks, design-token validation, and NativeAOT packaging. Native interop fields and framework template resources remain. |

Meeting close now waits for persistence before destroying the window. Failed delete keeps the session writable. Title saves are separately owned so a title edit does not swallow the following Pause or End click. Main-window shutdown retains a failed meeting owner for retry.

## Paired managed measurements

Baseline is commit `235affb`, whose production code matches the original review baseline. Current source is the implementation checkpoint containing this report. Both probes ran as Release .NET 10 JIT processes on the same Windows x64 host, an AMD Ryzen AI 7 PRO 350 with 8 cores and 16 logical processors. These are warm synthetic workloads, not NativeAOT application measurements. Other applications remained running; there is no sampled CPU or I/O profile.

Five independent processes per side ran five samples per case. Process order alternated baseline/current and current/baseline. Case order rotated inside each process. Setup and warmup were excluded. All output assertions passed. The table includes all 25 samples per side for each selected workload. Allocation counts are process-wide managed allocations, not retained memory or native working set. Coarse CPU counters are retained in the raw data.

| Warm workload | Baseline median ms | Current median ms | Baseline range ms | Current range ms | Baseline/current allocated bytes |
| --- | ---: | ---: | --- | --- | ---: |
| Auto identity, 32 MiB main plus 16 MiB sibling | 111.870 | 3.712 | 76.848 to 118.105 | 2.150 to 8.260 | 539,560 / 13,712 |
| List 300 meeting summaries | 514.483 | 181.810 | 439.554 to 846.230 | 141.175 to 262.438 | 37,442,712 / 271,864 |
| Attribution, 120 minutes | 17.179 | 13.050 | 4.464 to 42.807 | 10.073 to 26.058 | 4,043,000 / 2,150,160 |
| Speaker matching without observations, 120 minutes | 0.878 | 0.223 | 0.321 to 22.678 | 0.150 to 0.486 | 68,200 / 160 |
| Full durable save, 120 minutes | 12.920 | 16.831 | 7.106 to 337.990 | 11.028 to 51.139 | 11,328 / 11,648 |

The warm identity and listing observations support the intended reduction in repeated work. Attribution allocated 46.8% less, but overlapping timing ranges do not establish a reliable latency improvement. Full durable saves did not become cheaper in this comparison; bounded persistence removes them from recognition callbacks. No overall app speedup is claimed.

[Raw samples](performance-probe/fix-comparison.csv), [all workload summaries](performance-probe/fix-summary.json), and the [current probe](performance-probe/Program.cs) are retained. The original probe is available at `235affb`; its API calls differ from the current probe. Fixtures use synthetic transcripts and random DLL bytes that are never executed. The public native WAV is used only for separate native checks.

To reproduce, archive `Ansible.Core` and `docs/reviews/performance-probe` from `235affb` into an isolated baseline directory. Build that probe and the current probe in Release with separate `--artifacts-path` directories. Invoke each built `Ansible.Tests.dll` with its own fixture directory five times, alternating side order. Preserve each generated `measurements.json` before the next process. The probe is outside the solution and deliberately uses the existing test friend-assembly name for diagnostics.
